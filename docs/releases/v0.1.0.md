# easy-host 0.1.0

**Release date:** 2026-10-30

## Summary

easy-host 0.1.0 is the first recorded release of the CLI that turns a git repository into a long-running, self-hosted HTTP service on one Linux host. It clones the repository, builds an image with Railpack, runs it under rootless Podman with `--restart=always` on one declared host port, health-gates every update, keeps the previous image for rollback, and keeps named volumes unless you explicitly ask to delete them.

The version comes from `package.json`. No `v0.1.0` git tag and no npm publication exist in this repository; install from a checkout or a packed tarball as described below.

## Highlights

- **Ten commands, no daemon:** `add`, `list`, `status`, `logs`, `update`, `rollback`, `remove`, `config`, `doctor`, `version`. There is no scheduler, webhook receiver, TLS terminator, or reverse proxy.
- **No Dockerfile required:** Railpack detects Vite/React, Node/Express, and Python/FastAPI, and exports through a pinned rootless BuildKit.
- **Health-gated replacement:** a failed candidate is stopped and the previously serving image is restarted. A failed build leaves the old container untouched.
- **One-step rollback:** exactly two images are retained per app, so `rollback` swaps the pair and a second run returns to the newer image.
- **Data safety by default:** `remove` keeps named volumes unless `--volumes` is passed, and only deletes volumes whose `io.easy-host.app` label matches.
- **Scriptable output:** a fixed eight-code exit taxonomy and `schemaVersion: 1` JSON with secrets redacted.

## Compatibility and Prerequisites

- Linux on `x86_64` or `aarch64`.
- Rootless Podman `>= 5.7.0, < 6.0.0`. Podman 6.x is excluded while that major line is unstable.
- User lingering enabled (`sudo loginctl enable-linger "$USER"`), so `podman-restart.service` can replay containers at boot.
- A Docker-compatible image loader for Railpack's export step; `podman-docker` provides it on the gate host.
- git 2.40 or newer and Node.js 24 or newer.
- One free host port per app in the range `1024` to `65535`. Privileged ports are unsupported.
- Disk space for two images per app plus the build cache.

`easy-host doctor` verifies the host and prints a remediation command for each failing check. The complete matrix and upgrade paths are in [Host prerequisites](../operations/prerequisites.md).

## Installation or Upgrade

There is no in-place upgrade from an earlier easy-host release; 0.1.0 is the first recorded release.

**From a checkout:**

```sh
git clone <repository-url> easy-host
cd easy-host
npm install
npm install -g .
easy-host version
easy-host doctor
```

**From a packed tarball:**

```sh
npm install
npm pack
npm install -g ./easy-host-0.1.0.tgz
```

The `prepare` script builds `dist/`. Do not install with `npm install -g git+<repository-url>#v0.1.0`: npm prepares a git dependency before devDependencies are available, so that form fails to build. Because no tag exists, pin the verified commit in your deployment record instead.

Users of the previous `react-hoster` name should read the [migration note](../MIGRATION.md); there is no automatic conversion of old state because the old project documented none.

## Known Limitations

- **No TLS, reverse proxy, or authentication.** Published ports are plain HTTP. Ingress, certificates, and access control are operator responsibilities; the [Tailscale guide](../operations/tailscale.md) is one worked example.
- **Updates are not zero-downtime.** The app has one fixed host port, so a swap briefly stops serving while the candidate starts and is probed.
- **One repository, one service.** Multi-service and compose-style stacks are out of scope.
- **Three claimed stacks.** Railpack may detect other providers, but only Vite/React, Node/Express, and Python/FastAPI are supported by the fixture suite.
- **Two images only.** Rollback reaches the previous image, not an arbitrary history.
- **No backup, restore, or export command.** Volumes and state must be backed up with Podman and file-copy tooling.
- **No scheduler or monitoring.** Recurring updates use a systemd user timer; health is reported by `status`, not pushed.
- **No direct start/stop command.** Podman owns container start and stop; easy-host replaces containers through `update` and `rollback`.
- **A tailnet-IP bind is unsupported.** `bind` accepts only `0.0.0.0`, `127.0.0.1`, and `::`, and the readiness probe always targets `127.0.0.1`.
- **No package-registry distribution.** The package is `private`; there is no npm publish path.

## Validation

- The v0.1.0 release gate was run by the maintainer on 2026-10-30 on Ubuntu 26.04.1 LTS (aarch64, Linux 7.0.0, Podman 5.7.0 rootless, `Linger=yes`, Node.js 24.22.2, git 2.53.0) with an empty state root and requests from a second LAN host. Commands, exit codes, timings, and transcripts are in the [release-gate record](../operations/release-gate-v0.1.0.md).
- The gate exercises four outcomes: LAN reachability, return after reboot, a broken update keeping the previous version serving, and rollback restoring the previous image.
- The default suite (`npm test`) covers unit, documentation-drift, packaging-manifest, and documentation-link checks with no Podman, network, or root. `npm run typecheck` and `npm run lint` are part of the release checklist.
- Host-level integration tests are gated behind `EASY_HOST_INTEGRATION=1` and are not part of the default run. No continuous-integration workflow is published in this repository, so the local suite and the recorded gate are the evidence.

## Security and Privacy

- App containers run rootless, without `--privileged`, host networking, or extra capabilities.
- Secrets are read from a mode-`0600` file and passed as environment values. They are never written into `config.toml` and are replaced with `[redacted]` in output.
- `remove` deletes only volumes whose `io.easy-host.app` label matches the app, and never a host filesystem path.
- easy-host sends no telemetry. Its network access is limited to your git remote, the pinned Railpack release, and the registry used by BuildKit.
- There is no authentication layer. Anyone who can run the CLI as the owning user controls every app.
