# Packaging and Docs Detail

Load this file when editing `package.json`, completions, the README, operations guides, references, or the docs tests.

## Package fields

| Field | Value | Why |
|---|---|---|
| `name` | `easy-host` | Product name; repository rename is separate |
| `type` | `module` | ESM CLI |
| `bin.easy-host` | `dist/cli/index.js` | Built entry with shebang |
| `engines.node` | `>=24` | Matches the host prerequisite |
| `files` | `dist`, `completions`, `README.md`, `LICENSE`, `docs/operations`, `docs/reference` | Runtime payload only |
| `scripts.build` | `tsc -p tsconfig.build.json` | ESM emit to `dist/` |
| `scripts.prepare` | build | Install from clone or git URL works |
| `scripts.test` | unit suite, no Podman, no network | Default gate |
| `scripts.test:integration` | gated suite | `EASY_HOST_INTEGRATION=1` |
| `scripts.test:packaging` | pack, clean-prefix install, run | Release gate |

No npm publish, no `postinstall` download, no single-binary build in v1.

## Install paths

```bash
# from a clone
git clone <repo> && cd <repo> && npm install && npm install -g .

# from a git tag
npm install -g "git+https://<host>/<repo>.git#v0.1.0"

# from a packed tarball
npm pack
npm install -g ./easy-host-0.1.0.tgz
```

Each path must produce a working `easy-host` binary; the packaging test covers the tarball path and asserts the clean prefix.

## Completions

| File | Shell |
|---|---|
| `completions/easy-host.bash` | bash |
| `completions/easy-host.zsh` | zsh |
| `completions/easy-host.fish` | fish |

- Generated by `scripts/generate-completions.ts` from the commander program.
- Deterministic: same program produces byte-identical files.
- The test regenerates into a temp directory and compares.
- Installed by the operator manually; no install hook, no completion subcommand.

## Docs gates

| Test | Fails when |
|---|---|
| `tests/docs/links.test.ts` | A relative link is missing, a required heading is gone, a named command is not in the CLI, stale React-only branding appears outside `MIGRATION.md` |
| `tests/docs/reference.test.ts` | A CLI command or flag is undocumented, a schema key is missing from the config reference, exit codes differ |
| `tests/unit/completions.test.ts` | Committed completions differ from regenerated output, or a completion subcommand exists |
| `tests/packaging/install.test.ts` | The tarball lacks `dist` or runtime docs, includes tests or secrets, or the installed binary fails |

## Common doc claims to verify

- Podman floor and 6.x exclusion.
- Lingering is mandatory for `--restart=always` survival.
- Ports at or above 1024.
- No daemon, scheduler, TLS, reverse proxy, or telemetry.
- Volume retention unless `--volumes`.
- Two-image rollback window.
- Exit codes `0–7` as documented.

Any claim that is not true of the current binary is a documentation bug, even if the PRD says it should be true.
